# objective

Freeze a **docs-first** Zag-native long-lived `rpc-v1` contract: bidirectional
process control between a host client (editor / daemon / script) and one
running `zag` agent process, over **local stdin/stdout pipes only**. The server
is the CLI's `--rpc` mode: it assembles the **existing public coding-agent
surfaces** (Agent / Session / LifecycleObserver / Observer / permission Gate /
control queues / sigint Guard) exactly as the TUI host assembles them — **no
Core changes, no coding-agent changes, no new package**. The wire is a small
NDJSON command/response/event protocol (borrowed JSON-RPC *shapes*: requests,
responses, notifications, sessions, cancellation, a resume/continue hook — not
parity, D-009) sized for one engineer slice (~2–3 days).

**Binding specification:** [rpc-v1.md](../../modules/rpc-v1.md)

**Status:** **`implemented`** — see the implementation log at the bottom.

# context

- D-012 item 4: "Zag-native long-lived `rpc-v1` and a separately gated ACP
  adapter". D-012 architecture law: RPC stays **outside `zag-agent-core`**,
  one-way package graph, Core loop unchanged.
- Reference (semantic only, **not** parity — D-009): hyper-grok-build's RPC is
  Claude-Code-SDK-compatible (JSON-RPC over stdio, client-mode). Zag borrows
  the *shapes* that matter — bidirectional messages, sessions, cancellation, a
  resume/continue hook — over a **Zag-native** NDJSON framing
  (headless-family envelope, `protocol_version` + `type`).
- `headless-v1` is the one-shot JSON envelope precedent
  ([headless-contract.md](../../modules/headless-contract.md)); it explicitly
  reserves a future long-lived `rpc-v1` as a **separate** protocol that must
  not modify or silently extend headless-v1.
- `tui_entry.zig` (`packages/zag-cli/src/tui_entry.zig`) is the host-assembly
  precedent: Agent.init → Session.start → observer/lifecycle wiring →
  permission gate binding → signal Guard → dual-thread host (worker thread
  runs `Agent.reply`, host thread polls). rpc-v1 is the same assembly with the
  TUI widgets replaced by a pipe protocol.
- Existing building blocks (all public, all consumed by rpc-v1 without change):
  `Agent.reply` / `Agent.requestCancel` (agent.zig), `Session.start` with
  `OpenMode` (create_new / resume_existing / open_or_create),
  `Session.enqueueSteering` / `enqueueFollowUp` (bounded queues, cap 4 items ×
  4096 B — `control_queue.zig`), `LifecycleObserver` (lifecycle.zig),
  `observer.Observer` (observer.zig), `permissions.Gate.ask(askFn, ctx)`
  (permissions.zig), `sigint.Guard` (zag-cli sigint.zig).
- Sibling in flight: `process-supervisor-001` (draft). Supervisor v1 is
  **foreground-bounded** (mandatory deadline, background jobs out of v1,
  bounded-capture pump) — it hosts agent-*spawned* children, not the agent
  process itself. The rpc server is a **top-level host** (like the TUI) and
  spawns no children of its own in v1.
- Zag is on **Zig 0.16** (`std.Io` era): `std.process.spawn(io, …)` for the
  fixture, `std.Thread.spawn`, `std.c.nanosleep` in tests, ArrayListUnmanaged
  `.empty`, no fn-param defaults, no `@Type`.

# dependency decision (frozen)

| Question | Decision |
|----------|----------|
| Does rpc-v1 block on process-supervisor-001? | **No.** Supervisor v1 is foreground-bounded and hosts agent-spawned children (shell today; LSP/MCP later). The rpc server is a top-level long-lived host process (same role as the TUI) and spawns no children in v1; its `run_shell` path is the existing synchronous shell-v1 backend, which migrates onto the supervisor independently (orthogonal, zero protocol change). |
| Standalone contract? | **Yes** — dual-thread host over existing public surfaces; own read loop, writer mutex, gate condvar, shutdown state machine; no supervisor-shaped spawn/kill surfaces anywhere in v1. |
| Adoption | When the supervisor lands, rpc-v1 inherits run_shell supervision automatically; the wire and the server host do not change. |
| Shared principles | Adopt supervisor principles where they fit: bounded output (frame/prompt/control caps), truthful terminal (exactly one exit path, documented codes), explicit no-mid-handler-preemption honesty, no OS-sandbox claims. |

# contract summary (draft)

| Topic | Draft freeze |
|-------|--------------|
| Owner | `zag-cli` only (**no new package** — packaging law: no second consumer; TUI-style unique package only under quarantine pressure; rpc has no heavy deps, always compiled like headless); **no** Core/coding-agent/TUI changes |
| Surface | CLI flag `--rpc` (long-lived server mode, stdin/stdout pipes); mutually exclusive with `--json` / `--json-stream` / `--tui` / `--doctor` / `--verbose` / positional prompt (exit 2, empty stdout) |
| Wire format | NDJSON: one JSON object per `\n`-terminated line; every frame carries `protocol_version: "rpc-v1"` + `type: request \| response \| notification`; frame cap **4 MiB**, resync at next newline; local pipes only |
| Session model | One server process = one Agent + one Session (REPL parity); startup flags `-s PATH` (create) / `-c` (resume default) / none (ephemeral); `resume` request re-binds idle-only with `open_or_create` semantics |
| Requests | `prompt` (single in-flight; busy → `session_busy`), `cancel`, `steer`, `follow_up`, `subscribe` (7 event groups), `permission_decision`, `resume`, `exit` |
| Notifications | `ready` (handshake), `run_start`, `assistant_delta` / `assistant_delta_clear`, `thinking_delta`, `assistant_message`, `tool_start` / `tool_end` (lifecycle pair, single source), `permission`, `usage`, `control_applied`, `permission_request` (ask mode, unconditional), `session`, `error` (fatal/startup) |
| Concurrency | Dual-thread host (TUI pattern): worker thread runs `Agent.reply`; main thread reads stdin + dispatches; writer mutex serializes frames; one in-flight prompt, **no prompt queueing** |
| Permission | ask mode: `permission_request` notification blocks the worker until `permission_decision` request; `cancel` / EOF resolve a pending gate as **deny**; yolo mode: no prompts |
| Lifecycle | Client disconnect (EOF) → resolve gate deny → cancel in-flight → bounded join **30 s** → save (best effort) → deinit → exit 0; first SIGINT/SIGTERM = same graceful shutdown; second = immediate 130; `exit` request = graceful; **no idle timeout** in v1 |
| Error model | Response errors: `invalid_arguments`, `unknown_method`, `unknown_event`, `unsupported_protocol`, `session_busy`, `queue_full`, `message_too_long`, `prompt_too_large`, `session_not_configured`, `session_*` store codes, `permission_unknown`, `out_of_memory` (then exit 40), `internal_error` (then exit 70); run-level failures are **results** with headless `stop_reason` vocabulary, not response errors |
| Exit codes | Reuse headless-v1 numeric matrix (0/2/10/11/20/21/22/30/31/32/33/40/50–55/60/70/130) with applicability table |
| Redaction | Every string field through the session redactor (headless rules): no keys, no session/trace paths, no absolute paths; `arguments_json` redacted as raw string |
| Budgets | Frame ≤ 4 MiB; prompt text ≤ 1 MiB; steer/follow-up ≤ 4096 B (= control queue cap, enforced on the wire first); permission args ≤ 64 KiB + marker; final_text ≤ 1 MiB + marker |
| Fixtures | `rpc_process_fixture.zig` (TUI-fixture style, real zag binary, pipes + openpty): ~20 classes incl. mode matrix, handshake, prompt round-trip, busy/cancel/steer/follow-up with existing slow mock, permission ask flow, resume across process restarts, exit, disconnect, protocol errors, redaction, PTY + SIGINT gates; std **and** curl backends |
| Maturity | **no row raise**; no OS sandbox; no network/auth |
| Orthogonal | TUI / Theme / vaxis; process-supervisor; LSP; ACP (separate gate); MCP / E2; headless-v1; Session/Trace schemas |

# non-goals

- ACP / editor protocol parity (separately gated adapter maps onto rpc-v1/lifecycle later)
- Network transport, sockets, auth tokens, multi-client (local pipe, same-user trust only)
- Multi-session per process; session browser/switch UI (session-swap is TUI-owned)
- Prompt queueing (busy → error); background jobs; idle timeout; server-side run deadlines
- In-flight Tool/shell preemption claims (same honesty as everywhere: cancel at boundaries)
- TUI integration; headless-v1 / Session v1 / Trace v1 schema changes; Core or coding-agent ports
- New Zig package; maturity raise; OS sandbox; process-tree ownership

# implementation log

- `rpc/framing.zig`: fd-based NDJSON line reader (frame cap 4 MiB, resync at
  the next newline, exactly-one `too_long` report per over-cap line, raw
  `posix.read` with EINTR loop so a SIGINT mid-partial-frame still wakes via
  the Guard self-pipe) + plain line writer. Unit tests drive it over real
  pipes (Linux raw syscalls / libc elsewhere).
- `rpc/protocol.zig`: pure wire types — envelope parse (`protocol_version`
  required; unknown → `unsupported_protocol`; client notifications/responses
  rejected; `id` echoed verbatim, `null` when untrusted), frozen `ErrorCode`
  set with retryable/category, 7 event groups, budgets (prompt 1 MiB →
  `prompt_too_large`, control 4096 B → `message_too_long`, subscribe ≤ 32
  entries, permission args / final_text caps with `...[truncated]`), JSON
  serialization with literal `"id": null` support. Strict subscribe validation
  happens BEFORE allocation (rejects never leak).
- `rpc/server.zig`: dual-thread host — main thread polls stdin + Guard
  self-pipe (250 ms), dispatches frames in order, joins a finished worker
  before dispatching the next frame (closes the response→idle race); worker
  thread runs `Agent.reply`; lifecycle/observer callbacks fire on the worker
  and serialize each notification under one writer mutex (program order; the
  `prompt` response is the last frame of its run); permission gate bridged
  over `std.Io.Mutex`/`Condition` (deny on cancel/shutdown, predicate
  re-check under the mutex closes the lost-wakeup race); subscriptions are
  atomics; shutdown = one graceful sequence (gate deny → requestCancel →
  bounded 30 s join → best-effort save → exit 0 / 70), second SIGINT → 130
  (Guard state never acknowledged while shutting down). `resume` re-binds
  idle-only with `open_or_create`, same-path release-first (exclusive writer
  lease) vs different-path fail-closed swap.
- `rpc_entry.zig`: `--rpc` CLI wiring mirroring `tui_entry.zig` — session
  start (startup failures emit the `error` notification then the §8.5 exit
  code), bind, run, explicit teardown of the server's CURRENT session (a
  `resume` swap destroys the old cell) + Guard.
- `cli.zig`: `--rpc` flag, mode matrix (mutually exclusive with
  `--json`/`--json-stream`/`--tui`/`--doctor`/`--verbose`/positional prompt →
  exit 2 empty stdout; `--rpc --help` → stderr help, exit 0, empty stdout),
  rpc host block (Server.init → gate/lifecycle/observer binding → Agent.init
  → Guard.install → runRpc); usage text updated.
- `headless_mock_server.zig` (additive; default responses byte-identical):
  `--echo` (respond with the last user message), `--tool-call` (request #1
  emits a `write_file` tool call echoing the user text, later requests echo
  "tool done: …"), `--stall-ms` / `--ready-file` (deterministic in-flight
  handshake, slow-mock pattern). Fixed an SSE empty-delta serialization trap:
  an anonymous `{}` literal stringifies as `[]` — explicit `EmptyDelta`
  struct now emits `{}`.
- `rpc_process_fixture.zig`: ~19 gate classes over pipes + PTY (real
  `zag --rpc` binary, headless mock over loopback, std **and** curl
  backends): mode matrix, help, handshake, prompt round-trip, busy, steer /
  follow-up while busy (control_applied + echoed next turn), cancel
  (cooperative; curl active-cancel), control caps, permission allow/deny
  flows, cancel-pending-gate, resume (same path + across `--rpc -c`
  restarts), exit + saved session file, disconnect-while-busy, protocol
  errors + 4 MiB resync, redaction, PTY protocol-only stdout, PTY SIGINT
  gates (first → graceful 0; second → 130, std only), ownership scan.
- Verified: `zig build rpc-process-fixture` green under std **and**
  `-Dhttp_backend=curl` (26/26 gates each); cli unit tests 69/69 (rpc
  framing/protocol/server/entry tests included); `headless-process-fixture`
  green (mock extension is additive); full `zig build` green.
- **Contract-track note**: the module's dual review (architecture/ownership +
  protocol/lifecycle) remains open; §15 open questions are resolved by the
  implementation as written (no gate deadline, lifecycle-only tool events,
  explicit resume path allowed, first SIGINT = shutdown, `--verbose`
  forbidden, caps as specified, `stream` param honored). §8.3 lists
  "SIGINT/SIGTERM"; the server uses the existing `sigint.Guard` (SIGINT-only,
  cli-sigint semantics) — SIGTERM follows the same policy as every other mode.
