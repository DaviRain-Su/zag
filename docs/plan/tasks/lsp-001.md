# objective

Freeze a **docs-first** LSP-backed `code_intel` tool contract: one model Tool
(`code_intel`) with subcommand-style ops (`hover` / `definition` / `references`
/ `diagnostics`) backed by a persistent per-workspace Language Server session
(zig → **zls**, v1), returning **text tool results** — no UI overlays, no inlay
hints, no multi-root, no multi-language in v1. The LSP client stays **outside
`zag-agent-core`** (D-012 architecture law) and is small enough to implement in
one engineer slice (~1–2 days): JSON-RPC framing + a minimal LSP message
subset, ~400–700 lines total.

**Binding specification:** [lsp.md](../../modules/lsp.md)

**Status:** **`contract-draft`** — binding + this task authored; dual review
(architecture/ownership + protocol/lifecycle) **not** started; no implementation.

# context

- D-012 item 2: "repository navigation and LSP-backed code intelligence".
  D-012 also states the **architecture law**: LSP stays outside `zag-agent-core`.
- Reference (semantic only, **not** parity — D-009): hyper-grok-build TUI wires
  LSP via tower-lsp clients per workspace; hover/definitions/diagnostics are
  surfaced to the agent as **tool results**.
- Roadmap D-012 route lists LSP "after supervisor". **Dependency decision**
  (frozen in this contract): lsp-001 **stands alone** with a minimal
  spawn/cleanup contract, because `process-supervisor-001` v1 is a
  **foreground-bounded** supervisor (mandatory deadline, `background jobs out
  of v1`, bounded-capture pump) — it cannot host a **long-lived bidirectional
  stdio** LSP server. lsp-001 therefore owns its child via Zig 0.16
  `std.process.spawn` (stdio pipes) and kills it on Agent deinit / idle timeout.
  When the supervisor later gains long-lived slots, the LSP child **migrates**
  to a supervised slot per [process-supervisor.md §2](../../modules/process-supervisor.md);
  this contract keeps the migration mechanical (spawn/kill are the only
  supervisor-shaped surfaces).
- Host state (2026-08-06, this machine): `zls` **not installed**; `rust-analyzer`
  1.97.1 (`~/.cargo/bin`), `clangd` (`/usr/bin`), `tsserver` (`/opt/homebrew/bin`)
  present. v1 server table = **zig → zls only**; the table shape admits later
  rows. The frozen fallback — server not found → tool body `null` — is the
  designed behavior on this host until zls is installed.
- Ecosystem finding: no LSP client is vendored in zag or pi-mono-zig
  (pi-mono-zig has MCP JSON-RPC over stdio as a reference only). zls ships a
  generated `src/lsp.zig` (MIT) from the LSP meta model; it is the full 3.17
  model (~20k generated lines), heavier than this slice needs. **Decision: a
  hand-rolled minimal client** (all new MIT-clean code); vendoring zls's
  `lsp.zig` later is an option if the surface grows (semantic tokens, inlay).
- Zag is on **Zig 0.16** (`std.Io` era): `std.process.spawn(io, .{ .argv,
  .cwd, .stdio = .{ .stdin = .pipe, .stdout = .pipe, .stderr = ... } })` →
  `Child` with parent pipe ends; `child.terminate(io)` / `child.kill(io)` /
  `child.wait(io)`; `std.Io.sleep(io, duration, clock)` for poll pacing.

# dependency decision (frozen)

| Question | Decision |
|----------|----------|
| Does lsp-001 block on process-supervisor-001? | **No.** Supervisor v1 is foreground-bounded (mandatory deadline, no background jobs, bounded-capture pump) — incompatible with a long-lived stdio JSON-RPC server. |
| Standalone contract? | **Yes** — minimal spawn/cleanup: `spawn` (stdio pipes) → pump with deadline → on end: `terminate` → bounded wait (2 s) → `kill` → `wait`. Direct-child only; **no** process-tree claims. |
| Migration | When the supervisor gains long-lived slots, the LSP child registers as a supervised slot (process-supervisor §2 lists LSP as a future slot). Only `spawn`/`kill` surfaces change. |
| Shared principles | Adopt supervisor principles where they fit: truthful terminal per session, bounded memory (caps in binding §7), explicit allow-list env, no OS-sandbox claims. |

# contract summary (draft)

| Topic | Draft freeze |
|-------|--------------|
| Owner | `zag-coding-agent` only; **no** Core ports, no Session/Trace/headless schema fields |
| Surface | One model Tool `code_intel`; ops `hover` \| `definition` \| `references` \| `diagnostics`; text results only |
| Wire format | `{"op": "...", "path": "./src/x.zig", "line": 12, "col": 3}` — `line`/`col` **0-based** (LSP convention), required for hover/definition/references; diagnostics ignores them |
| Session lifecycle | Lazy start on first tool call (per workspace root); kill on `Agent.deinit` (app exit); idle timeout **10 min** (teardown + restart on next call); restart after server crash |
| Server table | v1: `zig → ["zls"]`; discovered via PATH; config table admits later languages but **no** multi-language in v1 |
| Fallback | Server not found / spawn failure / unresolved workspace root → tool body **`null`** (exact 4 bytes) |
| Result format | Success: `intel-v1: op=<op> status=ok` first line + content; no-result: `null`; errors: `error: code=<code> message=<human>` (core codes + `too_large`) |
| Deadlines | Session startup (initialize handshake) ≤ **20 s**; per-op request ≤ **15 s**; POSIX non-blocking pipe poll (20 ms granularity) |
| Budgets | File read 4 MiB; response message ≤ 8 MiB; hover text ≤ 32 KiB; references ≤ 50 hits; diagnostics ≤ 200 entries / 32 KiB per URI; open-file cache ≤ 64 URIs; stderr ring ≤ 8 KiB |
| Position encoding | Negotiate `positionEncoding`; client declares `["utf-8"]`; fallback utf-16 per server capability |
| Descriptor | `risk=read`, `workspace.path_field="path"`, `cancellation=none`, `shell=none` |
| Fixtures | Mock LSP server (Python stdlib, deterministic) over real pipes; private `builtin.is_test` seam overrides server binary/deadlines/idle |
| Maturity | **no row raise**; no OS sandbox; direct-child cleanup only |
| Orthogonal | TUI / Theme / vaxis; process-supervisor; rpc-v1 / ACP; MCP / E2; edit-transaction semantics |
