# Headless process contract

This document defines the public machine interface for the `zag` CLI when invoked with `--json` or `--json-stream`. It is the stable contract for headless automation, CI wrappers, and future ACP/editor integrations.

## Status

- Protocol version: `headless-v1`
- Default CLI behavior is unchanged: without `--json` / `--json-stream`, `zag` prints final text to stdout and keeps verbose/cost/errors on stderr.
- This contract is a post-H **Headless/Process SDK Gate**. It does not imply TUI, ACP, editor protocol, OS sandbox, or C ABI stability.

## Modes

| Flag | stdout | Semantics |
|------|--------|-----------|
| `--json` | Exactly one JSON line: a `result` or `error` envelope. | One-shot run; terminal is the only stdout output. |
| `--json-stream` | NDJSON event stream ending in exactly one terminal event (`run_end` or `error`). | Streaming progress + terminal. |

Both modes are mutually exclusive with each other and with the interactive REPL. If both `--json` and `--json-stream` are present, or if a headless flag is combined with REPL invocation (no prompt), the CLI exits `2`.

`--stream` (provider-side SSE) is orthogonal: it controls whether the provider adapter requests streaming completions, but the headless protocol events are always generated by the CLI from the canonical reply.

## Common envelope fields

Every object written to stdout in headless mode contains:

```json
{ "protocol_version": "headless-v1", "type": "<event|result|error|doctor>" }
```

- `protocol_version` — stable string, currently `headless-v1`. Independent from the internal trace schema version.
- `type` — discriminates the object.

All other fields depend on `type`. No log line, diagnostic, or human prompt is ever written to stdout in headless mode.

## `--json` result envelope

```json
{
  "protocol_version": "headless-v1",
  "type": "result",
  "ok": true,
  "stop_reason": "completed",
  "turns": 1,
  "final_text": "Hello from Zag.",
  "usage": { "prompt_tokens": 10, "completion_tokens": 5, "total_tokens": 15 }
}
```

| Field | Type | Meaning |
|-------|------|---------|
| `ok` | bool | `true` for `completed`, `max_turns`, and `cancelled`; `false` for all other terminal `stop_reason`s. |
| `stop_reason` | string | One of the terminal stop reasons from `loop.StopReason`: `completed`, `max_turns`, `cancelled`, `timeout`, `unsupported_control`, `provider_error`, `session_error`, `trace_error`, `out_of_memory`, `invalid_toolset`, `invalid_context`. |
| `turns` | integer | Number of model turns in this run. |
| `final_text` | string | Assistant final text (redacted). |
| `usage` | object | `prompt_tokens`, `completion_tokens`, `total_tokens` from the provider. May be all zero for provider/configuration failures. |

## `--json-stream` event schema

The stream emits one object per line. The last line is always a terminal event (`run_end` or `error`). Non-terminal events may appear zero or more times.

### `run_start`

```json
{
  "protocol_version": "headless-v1",
  "type": "run_start",
  "zag_version": "0.5.0",
  "permission": "ask",
  "shell_policy": "protect"
}
```

- `zag_version` — product version string.
- `permission` — `ask` or `yolo`.
- `shell_policy` — `protect` or `off`.

No session path, trace path, or provider details are exposed.

### `assistant_delta`

```json
{
  "protocol_version": "headless-v1",
  "type": "assistant_delta",
  "text": "Hello "
}
```

A chunk of assistant text since the previous delta. In non-streaming provider mode the entire assistant text may be emitted as a single delta.

### `tool_call`

```json
{
  "protocol_version": "headless-v1",
  "type": "tool_call",
  "id": "call_123",
  "name": "read_file",
  "arguments": "{\"path\":\"src/main.zig\"}"
}
```

`arguments` is the raw JSON string requested by the model. The CLI redacts secrets before emitting; the field may contain the literal redaction marker if the raw text matched a configured secret.

### `tool_result`

```json
{
  "protocol_version": "headless-v1",
  "type": "tool_result",
  "name": "read_file",
  "body": "file contents..."
}
```

`body` is the Tool result body as seen by the harness, after redaction. Soft Tool errors are represented as text inside `body`, not as headless error envelopes.

### `permission`

```json
{
  "protocol_version": "headless-v1",
  "type": "permission",
  "tool_name": "write_file",
  "allowed": true,
  "remembered": false,
  "risk": "mutating"
}
```

### `usage`

```json
{
  "protocol_version": "headless-v1",
  "type": "usage",
  "prompt_tokens": 10,
  "completion_tokens": 5,
  "total_tokens": 15
}
```

### `run_end` (terminal)

```json
{
  "protocol_version": "headless-v1",
  "type": "run_end",
  "ok": true,
  "stop_reason": "completed",
  "turns": 1,
  "final_text": "Hello from Zag.",
  "usage": { "prompt_tokens": 10, "completion_tokens": 5, "total_tokens": 15 }
}
```

Fields match the `--json` `result` envelope. Exactly one terminal event is emitted per run.

### `error` (terminal)

```json
{
  "protocol_version": "headless-v1",
  "type": "error",
  "error": {
    "code": "provider_configuration",
    "message": "Missing API key.",
    "retryable": false,
    "category": "auth"
  }
}
```

## Error schema

Every headless error has:

| Field | Type | Meaning |
|-------|------|---------|
| `code` | string | Stable machine code (see Exit matrix). |
| `message` | string | Human-readable, redacted; no secrets, session/trace paths, or absolute paths. |
| `retryable` | bool | Whether the caller is expected to benefit from retry. |
| `category` | string | `auth`, `provider`, `session`, `runtime`, or `argument`. |

## Exit code matrix

The matrix applies **only in headless mode** (`--json` or `--json-stream`). Default-mode exit codes remain unchanged: `0` for success, `1` for runtime/harness errors, `2` for argument errors.

| Scenario | Exit | `ok` | Notes |
|----------|:----:|:----:|-------|
| `completed` | 0 | true | |
| `max_turns` | 10 | true | Normal return, but turn limit reached. |
| `cancelled` | 11 | true | Clean cooperative cancel (e.g., SIGINT). |
| `timeout` | 20 | false | End-to-end provider deadline fired. |
| `unsupported_control` | 21 | false | Backend cannot enforce required deadline/active-cancel. |
| `required_sandbox_unavailable` | 22 | false | Reserved for a future required-sandbox mode; currently no CLI path produces it. |
| `provider_configuration` | 30 | — | Missing API key, unknown provider, unsupported API style, missing base URL. |
| `provider_error` | 31 | — | Runtime provider/network/model/auth failure. |
| `invalid_toolset` | 32 | — | Loop start-up toolset validation failed. |
| `invalid_context` | 33 | — | Context/history validation failed. |
| `out_of_memory` | 40 | — | Allocation failure. |
| `session_not_found` | 50 | — | Resume target does not exist. |
| `session_already_exists` | 51 | — | Create target exists. |
| `session_invalid` | 52 | — | Parse or path validation failure. |
| `session_unsupported_schema` | 53 | — | Session schema version unsupported. |
| `session_busy` | 54 | — | Write-lock conflict / save conflict. |
| `session_io_failed` | 55 | — | Session persistence I/O failure. |
| `trace_error` | 60 | — | Trace persistence/serialization failure. |
| Invalid CLI args / REPL + headless | 2 | — | Unknown flag, missing value, illegal session path, or headless + no prompt. |
| Unexpected internal | 70 | — | Assertion or unrecoverable Zig error. |

## `--doctor` in headless mode

`zag --doctor --json` writes a single `doctor` envelope to stdout:

```json
{
  "protocol_version": "headless-v1",
  "type": "doctor",
  "doctor": {
    "project_instructions": "loaded",
    "test_entry": "present",
    "permission": "ask",
    "shell_policy": "protect",
    "real_file_containment": "enforced",
    "lexical_file_jail": "enforced",
    "secret_redaction": "enabled_on_agent_run",
    "provider_key_redaction": "deferred_until_provider_resolve",
    "os_sandbox": "not_implemented",
    "shell_containment": "not_path_contained"
  }
}
```

`--doctor` does not require a provider, API key, or network.

## `--help` in headless mode

`zag --help` with `--json` or `--json-stream` writes the human-readable help text to **stderr** and exits `0`, keeping stdout empty for protocol output.

## Redaction rules

1. Every string field emitted in headless mode is passed through the same redactor used for trace/session persistence (`Agent.activeRedactor()`).
2. Error messages must not contain API keys, session paths, trace paths, or absolute file system paths.
3. `tool_call.arguments` and `tool_result.body` are redacted as raw strings.
4. Provider configuration diagnostics on stderr already omit the key value; the headless error message omits it as well.

## Mapping to internal types

The public schema is intentionally independent from internal Observer/Trace types:

| Public event | Internal source | Notes |
|--------------|-----------------|-------|
| `run_start` | CLI run setup / trace run_start | No borrowed slices or paths. |
| `assistant_delta` | Observer `assistant_text` or non-streaming final text | Delta since previous event. |
| `tool_call` | Observer `tool_call` | `id`, `name`, `arguments` only. |
| `tool_result` | Observer `tool_result` | `name`, redacted `body` only. |
| `permission` | Observer `permission` | Tool name + decision. |
| `usage` | Observer `usage` | Token counts. |
| `run_end` | `Agent.completeWithSession` `Result` | Exactly one per run. |
| `error` | CLI harness error mapping | Exactly one terminal per failed run. |

Internal trace events (jail deny, shell deny, provider retry, compaction) remain in the trace file and are not duplicated on stdout.

## Non-goals

- TUI implementation.
- ACP/editor protocol (follows this contract, but is separate work).
- SDK in-process semantic changes; headless uses existing `Agent.Options.observer` / `toolset` / `Session` / `stop_reason`.
- C ABI / dynamic plugin ABI.
- OS sandbox implementation.
- Mid-flight Tool/shell preemption.
- Provider streaming completeness as a protocol guarantee: `--json-stream` does not require provider-side SSE; it only guarantees NDJSON events assembled by the CLI.
